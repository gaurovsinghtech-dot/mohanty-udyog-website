# Premium Industrial Website — Paper Plate Machinery Business

## ROLE

Act as a **senior UI/UX designer, creative director, motion designer, and senior Next.js developer**.

Build a premium, modern, highly interactive and conversion-focused website for a company that manufactures and sells **Paper Plate Making Machines, Raw Materials, Industrial Machinery and Spare Parts**, along with installation and after-sales support.

The website should NOT look like a generic industrial/manufacturing template.

It should feel like a **premium industrial technology brand** — modern, trustworthy, technically sophisticated, visually impressive, informative and conversion-focused.

The final result should be suitable for a real business and production deployment.

# BACKEND / DATABASE

Use a proper backend/database architecture.

Do not store products or leads only in frontend state.

## DATABASE (MANDATORY)

Use **MongoDB Atlas (Free Tier)** as the primary database.

### Requirements:

- Use MongoDB Atlas Free Cluster (M0)
- Store all persistent data in MongoDB
- Use Mongoose (recommended) or native MongoDB driver
- Use environment variables for secure connection string
- Never expose MongoDB credentials in frontend code

### MongoDB Collections:

#### 1. Products Collection

Stores all product data:

- name
- slug
- category
- images
- description
- specifications
- features
- applications
- price / priceType
- availability
- featured
- seo metadata
- timestamps

#### 2. Leads Collection

Stores all contact form submissions:

- name
- phone
- email
- company
- productInterested
- requirement
- message
- city (optional)
- state (optional)
- source
- status (new/contacted/qualified/converted/closed)
- timestamps

#### 3. Admin Collection (optional but recommended)

For authentication:

- username/email
- password (hashed using bcrypt)
- role (admin)

---

## RECOMMENDED ARCHITECTURE

Next.js\
↓\
API Routes / Server Actions\
↓\
MongoDB Atlas (Free Tier)\
↓\
Admin Dashboard

---

## MONGODB CONNECTION RULES

- Use a single reusable DB connection file
- Prevent multiple connections in development (hot reload safe)
- Use connection caching strategy

Example structure:

lib/\
mongodb.ts\
models/\
Product.ts\
Lead.ts\
Admin.ts

---

## ENVIRONMENT VARIABLES

Store securely in `.env.local`:

MONGODB\_URI=your\_mongodb\_atlas\_connection\_string\
DB\_NAME=your\_database\_name\
JWT\_SECRET=your\_secret\_key

---

## DATA PERSISTENCE REQUIREMENT

All of the following MUST persist in MongoDB:

- Products created in admin panel
- Product updates/deletions
- Contact form submissions (leads)
- Lead status updates
- Admin authentication data

No critical data should rely on frontend state or local storage.

---

## FREE TIER CONSTRAINT HANDLING

Since MongoDB Free Tier is used:

- Optimize queries (avoid heavy aggregations)
- Use indexing for:
  - slug (products)
  - email/phone (leads)
  - createdAt (sorting)
- Avoid unnecessary large document nesting
- Use pagination for products and leads

---

## OPTIONAL (RECOMMENDED)

- Add MongoDB indexes for performance
- Enable basic backup strategy (Atlas built-in)
- Use validation at schema level (Mongoose)
